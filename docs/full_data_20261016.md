## Implementation

Version 0.2 adds SQLite-backed joins and measurement-cohort lookup, bounded
batch/cache sizes, streamed per-molecule feature output, and atomic result
publication. SQLite files live on node-local scratch and are removed after
completion. They are disposable working files, not restart checkpoints.

The original memory backend remains available for small samples. Both
backends use the same row conversion and measurement functions. The SQLite
path retains every selected genotype class and missing metric row and never
filters on methylation. Fraction 1 means the entire genotype ledger, not all
sequenced molecules: the upstream genotyper has already restricted that
population to primary plasmid alignments.

The two real imports used a 64-MiB SQLite cache, batches of 10,000 records,
a 10-GiB database limit, and `/tmp` on the allocated compute node. At most two
single-threaded full-data jobs ran concurrently within the four-CPU Slurm
allocation; lightweight validation used the remaining capacity. Group quota
and local scratch capacity were checked before running.

## Why full-plasmid recovery is low

| Run | Full plasmids | Partial plasmids | Concatemer-class reads | Mean partial-read length |
|---|---:|---:|---:|---:|
| 1 | 630,281 (33.6%) | 1,235,317 (65.9%) | 9,545 | 2,386 bp |
| 2 | 79,748 (2.8%) | 2,792,653 (97.2%) | 449 | 1,577 bp |

Percentages use the complete genotype ledger as denominator. The plasmid
reference is 4,647 bp. Run 2 contains 2,410,976 partial-class reads shorter than
half the reference length. Its low full-plasmid fraction therefore reflects a
population dominated by short reads, before methylation-based selection.
This describes the observed read population; it does not identify the causal
preparation, fragmentation, alignment, or sequencing step.

The imported labels have different definitions. Inspection of the current
upstream scripts shows:

- `plasmid_full`: the alignment spans both ends of the rotated reference,
  subject to an end tolerance, and query length does not exceed the concatemer
  threshold. Current script defaults are 50 bp and 1.1 times reference length.
- Ledger `full_length`: query length is within 50 bp of reference length.
  It is not the same test as alignment span.
- `NO_INSERT`: the genotyper did not recover the mutable sequence and the
  alignment does not overlap that interval. This can describe a fragment that
  misses the element; it does not prove an element deletion.

Script paths and checksums are saved in `classification_evidence.json`.
These are current-source explanations of imported labels, not a claim that
the historical scripts were byte-identical, and no structural labels were
recalled in this run.

The full-plasmid requirement also excludes potentially useful promoter data:
124,090 partial-class reads in run 1 and 194,450 in run 2 have assigned WT/SNV
genotypes and at least 10 passes. These counts precede exact BAM sequence and
interval verification. They identify a candidate sensitivity cohort, not
already validated extra measurements. A promoter-complete analysis would
need explicit sequence, alignment, and molecule-quality checks, with partial
and full-plasmid results kept distinguishable.

## Preliminary agreement and interpretation

Runs 1–2 now share 416 SNVs with at least ten measured molecules each. Their
descriptive correlations are 0.026 for the common-site MSP-fraction difference
and −0.127 for the region-wide small-footprint-fraction difference. There is
little positive concordance in these raw regional summaries. These are not
site-level footprint comparisons or calibrated hypothesis tests.

Unequal coverage, technical variation, sequence-dependent observability, and
regional averaging can affect these results. The result does not establish
that variants lack chromatin effects. Localized footprint changes need their
own readouts, null calibration, and uncertainty assessment. Run 3 additionally
differs in reaction conditions and upstream software, so it remains a separate
comparison rather than a pooled third replicate.
