Step A2 · Read accounting

Where does every read go, and should any of it come back?

Why

Only a quarter of run 3’s reads reach the analysis. We need to know what is discarded and why, and to decide what to recover using read properties alone, never variant effects.

What we did

Ran run 3’s ledger code and settings on runs 1–2. Gave each read the first filter it fails. Aligned off-design elements to WT, tracked errors by pass count, sampled run-3 base qualities and counted clones per SNV.

What we found

  • Run 3: 25% eligible. Designed indels (18%) are the largest exclusion.
  • Runs 1–2: mostly genomic or partial reads, and few clones per SNV.
  • The barcode rule rejects deep barcodes; A3 fixes it.

Source: results/analysis_v2_20261028/a2_accounting, a2_ledgers (tools/analysis_v2/a2_*.py)

Runs 1 and 2 were processed with exactly the run-3 ledger code and settings (only sample, input and output changed), on their October realignments to the NotI-rotated reference. HEK293T was processed by a different pipeline and is shown on its own slide.
